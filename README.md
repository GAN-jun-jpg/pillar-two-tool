# Pillar Two 全球最低税测算工具（本地确定性引擎 + 可选云端 Agent）

一个**本地运行**的 GloBE（支柱二）测算工具：导入辖区数据 → 校验 → 计算 ETR / 补税 →
QDMTT·IIR·UTPR 三层分配 → 结果审查 → 情景模拟（含架构调整与组合搜索）→ 报告与 GIR 导出。

**数字只有一个来源**：`calculator.py`。云端（可选）只负责"提动作、写解读、规划图表"，
**不产生任何数值**。

---

## 1. 快速开始

```powershell
# 1) 依赖（Python 3.12）
D:\python\python.exe -m pip install -r requirements.txt

# 2) 启动（默认端口 8501）
cd D:\德勤税务
D:\python\python.exe -m streamlit run app.py --server.port 8501
```

浏览器打开 `http://127.0.0.1:8501`。

**可选：启用云端 Agent**（缺密钥也能跑，只是没有云端解读/图表规划，见第 5 节）
```powershell
$env:DEEPSEEK_API_KEY = "你的密钥"
```

**⚠️ 改了任何被 import 的模块后必须重启 app** —— Streamlit 不会热重载 `calculator.py`
这类模块，只刷新页面会继续用旧代码。

## 3. 数据从哪来

支持三种导入：① 分别上传三张财报；② 一张工作簿多 sheet；③ **多辖区表**（一行一个辖区，
可含 DTL 台账）。金额单位取表头识别（元/千元/万元/百万元/千万元/亿元）。

**⚠️ 仓库里带的是演示数据**：`25辖区测试数据_方案A_118条台账.xlsx` 与本地方案库里的
"方案A / 方案B"。**用在真实业务前，第一件事是把演示数据与真实数据分库**
（用环境变量 `PILLAR_TWO_DB` 指向另一个库文件即可），并按财年核对口径
（SBIE 过渡率与安全港门槛都是逐年变的）。

已知数据质量问题：**方案A 末行是一条自然语言句子**（误粘贴），会被当成一个辖区 →
出现在辖区列表、报告与 GIR 里，建议删掉。

## 4. 哪些数字可以信

| 保障 | 说明 |
|---|---|
| 单一来源 | 所有数值只由 `calculator.py` 产出；界面、情景、搜索、报告、GIR 全部调用同一条管线 |
| 官方向量 | `test_oecd_vectors.py` 用 OECD 官方案例锁定关键机制（含 Art 2.3.2 抵免） |
| 结果审查门禁 | `Agent/tools/result_review_tool.py` 做确定性复核（分配守恒、净负债构成、税源三去处、**图表数字**）；审查不通过则不产出图表 |
| 对账巡检 | `test_reconciliation.py` 把"界面上必须成立的关系"逐条锁死（分项=合计、比例与金额同分母、UPE 自缴不漏不重） |
| 审计留痕 | 每次运行、规则发布、情景保存都写审计日志（"审计"页签） |

## 5. 边界（做不到的事，别猜）

- **实体层**：支持"同一辖区多实体"与**改设/新增/删除辖区**（结构动作），但**没有长期维护
  一张实体表**的编辑界面；GIR 与报告仍按**辖区**口径；
- **多母公司**：支持按持股拆分 IIR（含上层 Art 2.3.2 抵免），但**同一辖区多路径的完整
  官方算例（Example 2.3.2-2）未做**；
- **规则库**：覆盖主规则（ETR/SBIE/三层分配/安全港/递延税封顶与回转），
  **未覆盖** GloBE 的部分可选条款与特殊情形；`mapping_rules.json` 的所得税费用拆分
  仍缺更多财报附注场景；
- **组合搜索**：单目标；改设目标按 ETR 取前 3 个（压住选项数）；结论口径只会说
  "该子空间内最优 / 局部最优 / 启发式"，**从不声称全局最优**；
- **"调低利润"不是优化**：搜索把它标为非税务手段，默认不选；并默认要求
  "集团利润 + 覆盖税额不变"，避免用"少赚钱"换"少缴税"
  （`TestSearchNonTax` 相关测试锁定）；
- **云端不可用时**：只跑本地确定性流程，图表与计算照常（这是刻意保留的兜底）。
